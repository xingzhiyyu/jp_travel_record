# 精细海岸线分析与获取提示词

请分析本次行程哪些区域值得使用精细海岸线，先给出下载计划，不启动整片渲染，也不要未经确认下载大范围数据。

先阅读 AGENTS.md、README.md、docs/WORKFLOW.md，并检查当前海岸线加载与镜头计算代码。以实际实现为准，不假设已经支持自动分块、下载预算或替换内置区域。

## 一、确定分析依据

1. 优先使用已经核对的 `.resolved.json` 中各段真实路径，不只看起终点或线路名称。不要为了本次海岸线分析重新全量发现铁路目录。
2. 根据实际画面尺寸、每段目标缩放、换乘缩放和平移、结尾总览，计算或采样镜头视野。可调用现有镜头计算方法，但先确认接口。
3. 若拿不到真实镜头参数，明确标记“粗略估计”，不要把路线附近固定宽度的缓冲区当成精确画面范围。
4. 只使用当前项目、用户明确指定的文件和缓存；不要自行访问其他旧项目目录。

## 二、判断哪里值得精细化

将可见区域分为：

- 必要：近景经过海岸、港池、码头、人工岛、跨海桥或岸边车站，概化边界可能造成轨迹落海、岛屿消失或明显海陆错位。
- 有益但可后置：海岸在画面中持续可见，但远离轨迹；精细化主要改善辨识度。
- 不需要：海岸不在视野中，或只在远景／结尾总览短暂出现，概化陆地已经足够。
- 待核实：可见水面可能是河流、湖泊或独立港内水域。不能把所有水面错误都归因于 coastline；应判断是否需要另一类水体数据。

判断依据应包括：出现在哪一段、镜头缩放、海岸在画面中的位置、可见时长，以及错误是否影响旅行轨迹表达。距离阈值只作初筛，不作最终结论。

## 三、控制获取范围

1. 检查已有有效缓存和覆盖区域，避免重复获取。
2. 沿实际可见海岸选择小范围矩形，并留必要的镜头与几何边缘余量。不要直接下载整条长途行程的大包围框。
3. 优先选择收益最高的一个小区域验证，再考虑扩展。精确下载体积未知时写“未知”，不要按面积虚构字节数。
4. 不要为了内陆行程或低缩放总览下载整片精细海岸。
5. 区分“理想下载计划”和“当前程序实际会发出的请求”。尤其检查：新增自定义小区域后，渲染器是否仍强制下载重叠的内置大区域。若是，指出代码阻碍；不能宣称追加小区域已经减少了下载量。
6. 发现程序能力不足时，先说明最小必要改动，不未经授权改代码、停用整个海岸层或静默降低成片质量。

## 四、输出结果

用简短表格列出：

区域｜对应行程与镜头｜优先级｜精细化理由｜已有缓存｜建议 bbox（南、西、北、东）｜实际下载阻碍

随后说明：

- 最少应该获取哪些区域，哪些可以不下载；
- 哪些问题应交给河流／湖泊／港内水体层处理；
- 哪些判断尚需原始地图或代表性画面核实；
- 现有命令能否执行这份计划。仅列出已经核实存在的命令，不虚构参数。

若用户随后授权获取：串行请求、复用缓存、限制重试；429 退避等待，超时保存诊断。下载成功后仍需验证海陆方向、断裂、分区接缝，并检查少量实际渲染帧。不得跨海湾直线闭合、把空响应当成陆地，或以“下载成功”代替地理正确性验证。

保留 OSM / Natural Earth 署名，不上传用户行程、缓存或视频。

## 五、获得授权后获取与验证

执行前核对 `coastline --help` 和 travel_record/coastline.py。不改原始记录，不启动整片，不推送仓库。

先检查已有 `.resolved.json` 的实际 path 和当前缓存 `coastline-regions/`，区分内置精细覆盖、
新增覆盖与 Natural Earth 概化区域。根据路线和实际镜头视野选择沿海矩形范围，保留镜头余量；
不要只框站点，也不要为了内陆段下载全国海岸。范围依次为南纬度、西经度、北纬度、东经度。
每区经纬跨度不得超过 3 度；先选一个港区小范围验证，再逐区串行获取，不并发轰炸公共服务。

执行 `uv run travel-record coastline 区域英文名 --bounds 南 西 北 东`，使用与 render 相同的
`--cache-dir`。这是独立下载与注册命令，不会自动解析行程、自动划区或输出视频。
必须检查退出码和注册 JSON；成功须有完整 OSM coastline 几何、海陆方向一致、严格多边形化通过。
为空、断裂、方向矛盾或 Overpass 超时时保留诊断，不能直线闭合、编造陆地、把失败报告成成功。
失败可缩小或调整范围，核对原始 OSM 数据后有限重试；不要把改范围当作修复真实数据错误。

注册完成后，用实际渲染器输出包含新区域的少量核对帧，选港池、岛屿、岸边车站和区域边缘，
对照原始 OSM 几何检查海陆方向、缺口与接缝；必要时看日夜两种主题。
如果新旧区域重叠，说明自定义区域会后绘制，避免新旧快照日期不一致造成接缝。
只验证下载不等于视觉验证；没有看图就明确说明未做视觉核对。

交付区域名称、bbox、数据时间、实际来源、检查结果、未覆盖区域、失败原因和缓存位置。
注意 natural=coastline 不是所有水体：河流、湖泊、港内独立水面需要另行核实 water 数据层，
不能承诺这个命令会修复全部港区问题。视频继续保留 OSM / Natural Earth 署名。
缓存与用户行程不提交 Git；公开 OSM 派生数据前单独检查 ODbL 要求。
